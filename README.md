# ReSpace · ศูนย์ซ่อมสร้างชุมชน

เว็บแอปบริการสาธารณะซ่อมเครื่องใช้ไฟฟ้าฟรีสำหรับประชาชน
หน้าเว็บแบบ static (ไม่ต้อง build) เชื่อมกับฐานข้อมูลและระบบล็อกอินบน Supabase

## โครงสร้าง

    index.html            หน้าเว็บ
    assets/config.js      URL และ publishable key ของ Supabase
    assets/app.js         หน้าจอของประชาชน ช่าง และแอดมิน
    assets/styles.css     สไตล์ ธีมสว่าง/มืด
    assets/supabase.js    ไลบรารี supabase-js 2.117.3 (MIT)
    assets/qrcode.js      ไลบรารี QR (qrcode-generator 1.4.4, MIT)

## เปิดดูในเครื่อง

    python3 -m http.server 8080
    # เปิด http://localhost:8080

ต้องเปิดผ่านเซิร์ฟเวอร์ (localhost) และต่ออินเทอร์เน็ต เพราะข้อมูลอยู่บน Supabase

## ฐานข้อมูล (Supabase project: respace, ภูมิภาคสิงคโปร์)

กฎสำคัญทั้งหมดอยู่ในฐานข้อมูล ไม่ได้อยู่ในหน้าเว็บ แก้จากเบราว์เซอร์ไม่ได้:

- **สิทธิ์ (Row Level Security):** ประชาชนเห็นเฉพาะเครื่อง เคส การจอง และแจ้งเตือนของตัวเอง ช่างและแอดมินเห็นงานทั้งหมด บันทึกการดำเนินการเห็นเฉพาะแอดมิน ผู้ใช้แก้บทบาทตัวเองไม่ได้
- **คัดกรองความเสี่ยง:** ทำที่เซิร์ฟเวอร์ตอนส่งเคส เคสเสี่ยงสูงประเมินเป็น "ซ่อมเองได้" ไม่ได้
- **การจอง:** ตรวจโต๊ะ ช่าง เครื่องมือ และอะไหล่ในธุรกรรมเดียว มี unique index กันจองซ้อนแม้กดพร้อมกัน จองค้างได้ 2 คิว ไม่มาตามนัด 2 ครั้งพักสิทธิ์
- **สต็อก:** แยกคงเหลือ / กันไว้ / ใช้จริง คืนส่วนที่กันไว้เมื่อยกเลิก
- **QR:** รหัสสุ่ม ไม่มีข้อมูลส่วนตัว เช็กอินได้ครั้งเดียว เฉพาะเจ้าหน้าที่
- **ภาพเคส:** เก็บใน Storage แบบส่วนตัว (bucket `case-photos`) เห็นได้เฉพาะเจ้าของและเจ้าหน้าที่ ลิงก์ภาพหมดอายุใน 10 นาที

ฟังก์ชันที่หน้าเว็บเรียก: `submit_case`, `submit_assessment`, `request_info`, `booking_options`, `create_booking`, `cancel_booking`, `check_in`, `start_repair`, `call_tech`, `ack_call`, `take_over`, `save_result`, `return_tool`, `submit_review`, `mark_noshow`, `reset_noshow`, `set_tool_maint`, `restock_part`, `set_setting`

ประวัติ migration ดูได้ใน Supabase Dashboard → Database → Migrations

## ผลการทดสอบ

- ฐานข้อมูล: จำลองผู้ใช้ทั้ง 3 บทบาทเดินครบตั้งแต่จองจนปิดเคส และตรวจว่ากฎกันการกระทำที่ไม่มีสิทธิ์ได้จริง (เช็กอินเอง เลื่อนบทบาทตัวเอง จองโต๊ะผิดประเภท ซ่อมเองในเคสเสี่ยงสูง เช็กอินซ้ำ)
- หน้าเว็บ: ทดสอบทุกหน้าของทั้ง 3 บทบาทกับข้อมูลจำลอง ไม่มีข้อผิดพลาด ไม่มีการเลื่อนจอซ้ายขวาบนมือถือ
- การเข้าถึง (WCAG 2.1 AA ด้วย axe-core): 0 ข้อผิดพลาด ทั้งธีมสว่างและมืด 8 หน้าจอ
- เว็บจริง (GitHub Pages + Supabase, 14 ต.ค. 2026): ประชาชนส่งเคส C0005 → ช่างประเมิน → ประชาชนจองคิว B0005 ได้ QR → ช่างเช็กอินด้วยรหัส เริ่มซ่อม บันทึกผล คืนเครื่องมือ → เคสปิดอัตโนมัติ → ประชาชนรีวิว ได้แจ้งเตือนครบทุกขั้น ไม่มีข้อผิดพลาด (C0005/B0005 เป็นข้อมูลทดสอบ ลบได้)

## ก่อนเปิดใช้จริง

1. ปิด "อนุญาตเช็กอินก่อนวันนัด" (หน้าแอดมิน → บันทึก)
2. ลบบัญชีทดลองและข้อมูลตัวอย่าง
3. เปิด Leaked password protection ใน Supabase Dashboard → Authentication
4. ตั้ง Site URL และ Redirect URL ของอีเมลยืนยันให้ตรงกับโดเมนจริง
5. ตั้งนโยบาย PDPA: ระยะเวลาเก็บข้อมูล การลบข้อมูล และผู้รับผิดชอบ
6. แทนที่ "หน่วยงานท้องถิ่น (ตัวอย่าง)" ด้วยชื่อหน่วยงานจริง
7. ทดสอบการเข้าถึงกับผู้ใช้จริงและโปรแกรมอ่านหน้าจอ (NVDA / VoiceOver)
8. ลบบรรทัด `noindex` ใน index.html เมื่อพร้อมให้ค้นหาเจอ

## อัปเดตเฟส 2 (13 ต.ค. 2026)

- สแกน QR เช็กอินด้วยกล้องโทรศัพท์ (BarcodeDetector หรือ jsQR)
- ติดตั้งเป็นแอปบนหน้าจอโทรศัพท์ได้ (PWA: manifest.webmanifest, sw.js)
- เบอร์โทรย้ายไปตาราง `contacts` เห็นได้เฉพาะเจ้าของและแอดมิน คอลัมน์ `profiles.phone` เดิมปิดการอ่านแล้ว ลบทิ้งได้ภายหลังผ่าน Dashboard
- ยืนยันสิทธิ์คนในพื้นที่: แอดมินยืนยันผู้ใช้ที่หน้า "ผู้ใช้" และเปิด/ปิดกฎที่หน้า "ตั้งค่า" (ปิดอยู่)
- เตือนนัดอัตโนมัติในแอปล่วงหน้า 1 วันและ 2 ชั่วโมง (pg_cron ทุก 10 นาที)
- สถิติสาธารณะบนหน้าเข้าสู่ระบบ (`public_stats`)
- คำขอลบบัญชีและข้อมูล (PDPA): ประชาชนส่งคำขอในหน้าโปรไฟล์ แอดมินเห็นที่หน้า "ผู้ใช้" แล้วลบผู้ใช้ใน Supabase Dashboard → Authentication → Users ข้อมูลที่เชื่อมกันถูกลบตามอัตโนมัติ
- ตัวนับแจ้งเตือนที่ยังไม่อ่าน

## อัปเดตเฟส 3 (14 ต.ค. 2026): ระบบเพิ่ม 4 ระบบ

1. **แดชบอร์ดตัวชี้วัด** (แอดมิน → ภาพรวม): วัดผลเทียบเป้าโครงการ 4 ข้อ (ผู้ใช้ 5,000 คน / ลดรายจ่าย 50,000 บาท / ลดขยะ 1 ตัน / ความพึงพอใจ) เลือกปีงบ เดือน หรือทั้งหมด ส่งออก CSV เปิดใน Excel ได้ แก้เป้าและค่าแรงมาตรฐาน (เริ่มต้น 300 บาท/งาน) ที่หน้าตั้งค่า — ฟังก์ชัน `kpi_report`
2. **เวิร์กช็อปและใบรับรอง** (แอดมิน → อบรม, ประชาชน → เรียนรู้): เปิดคลาส จองที่นั่ง (กันเกินจำนวน) เช็กอินด้วย QR รหัส `WS-` ช่องเดียวกับคิวซ่อม ได้ใบรับรองพร้อมเลขที่ พิมพ์หรือบันทึก PDF ได้ ตรวจสอบความถูกต้องผ่านลิงก์ `?cert=เลขที่` โดยไม่ต้องล็อกอิน — ตาราง `workshops`, `workshop_seats`
3. **ช่างอาสาและช่างสูงวัย**: ประชาชนสมัครที่หน้าโปรไฟล์ แอดมินอนุมัติที่หน้าผู้ใช้แล้วตั้งเป็นช่างทันที ชั่วโมงงานคำนวณอัตโนมัติจากงานซ่อมและคลาสที่สอน บันทึกงานอื่นเพิ่มได้ — ตาราง `tech_applications`, `work_hours`, ฟังก์ชัน `hours_report`
4. **จุดรับทิ้งขยะอิเล็กทรอนิกส์** (หน้างาน / คลัง): ชั่งน้ำหนักจริง ถอดอะไหล่เข้าคลังทันที รายงานแยกเป็น "จัดการอย่างถูกวิธี" ไม่นับรวมขยะที่ลดได้ — ตาราง `ewaste_dropoffs`, `dropoff_parts`
5. **คิวสำรอง**: เมื่อวันที่เลือกเต็ม ลงชื่อรอได้ (สูงสุด 3 รายการ) เมื่อมีคนยกเลิกหรือไม่มาตามนัด ระบบเสนอคิวให้คนแรกและกันที่ไว้ 2 ชั่วโมง (ตั้งค่า `waitlist_hold_hours`) หมดเวลาแล้วเลื่อนให้คนถัดไปอัตโนมัติ — ตาราง `waitlist`

ทดสอบ: กฎในฐานข้อมูลทุกฟังก์ชัน (สิทธิ์ ความจุ การจองซ้ำ การกันที่) หน้าเว็บทั้ง 3 บทบาท และ axe-core 0 ข้อผิดพลาด 13 หน้าจอ ทั้งธีมสว่างและมืด

## อัปเดตเฟส 4 (14 ต.ค. 2026): Open Data และ AI ช่วยคัดกรอง

### ข้อมูลเปิด (Open Data)
- หน้าสาธารณะ `?open` (ไม่ต้องล็อกอิน) สถิติรวมรายเดือนและตามประเภทเครื่อง กราฟ ตาราง ดาวน์โหลด CSV / JSON สัญญาอนุญาต CC BY 4.0
- ฟังก์ชัน `open_data()` คืนเฉพาะยอดรวม ไม่มีข้อมูลบุคคล จำนวน 1–4 แสดงเป็น "<5" และค่าที่คำนวณจากกลุ่มเล็กจะเว้นว่าง

### AI ช่วยคัดกรองรูปถ่าย (ต้องตั้งค่ากุญแจก่อนใช้)
- Edge Function `ai-triage` (โค้ดใน `supabase/functions/ai-triage/`) ส่งรูปและอาการไปให้ Claude สรุปความเห็นเบื้องต้นให้ช่าง
- **ตั้งค่า:** สร้างกุญแจที่ console.anthropic.com แล้วใส่ใน Supabase Dashboard → Edge Functions → Secrets ชื่อ `ANTHROPIC_API_KEY` (เลือกรุ่นได้ด้วย `ANTHROPIC_MODEL` ค่าเริ่มต้น `claude-sonnet-5-5`) ระหว่างยังไม่ตั้ง ช่องยินยอมจะไม่แสดงและแอปทำงานปกติ
- ประชาชนต้องติ๊กยินยอมเองตอนส่งเคส (ตาราง `ai_consents`) ไม่ส่งชื่อหรือเบอร์โทรไปให้ AI
- ผลเห็นเฉพาะช่างและแอดมิน (ตาราง `ai_assessments`) เป็นความเห็นประกอบ ช่างตัดสินขั้นสุดท้าย
- AI ปรับความเสี่ยงได้ทางเดียวคือสูงขึ้น (ต่ำ → รอช่างพิจารณา) เมื่อพบสัญญาณอันตราย ไม่มีทางปลดล็อก "ซ่อมเองได้"
